# AGENTS.md — BongDesign

BongDesign is a self-hosted replica of the Carbon design system (site + MCP) for the Bongbetic team and their coding-agent harnesses. Spec: `.heimdall/spec.md` (runtime file, not committed; the spec issue is created at G3 and named in `.heimdall/STATE.md`).

## Commands

| Task | Command |
|---|---|
| Install (frozen: never rewrites the lockfile) | `cd site && npm ci` |
| Run (dev) | `cd site && npm run dev` (UI) · `BONGDESIGN_OPEN=1 PORT=8000 python3 server.py` (server, needs `site/dist`) |
| Build | `cd site && npm run build` |
| One test file | `python3 -m unittest tests.<name>` (test package added by the scaffold ticket) |
| Full suite | `cd site && npm run check:coverage` + `python3 -m unittest discover tests` + the HTTP smoke in CI |
| Type-check | none (plain JS site, Python stdlib server) |
| Lint / format | none configured — match surrounding style |
| End-to-end (acceptance tests: one per Success Criterion) | HTTP smoke against a booted server (see the acceptance tickets) |
| Services (podman) | none — `Containerfile` builds the deploy image |

## Module map

| Module | Paths | Public interface | Tests |
|---|---|---|---|
| shell | `site/src/shell/**`, `site/src/routes.*` | routed pages under Carbon UIShell (Header/SideNav) | coverage + HTTP e2e |
| pages | `site/src/pages/**` | home, overview card grid, component page, foundations, patterns, support/MCP pages | render-check SSR |
| explorer-data | `data/**`, `scripts/**` | generated component/token/icon indexes | `scripts/render-check.cjs` + validators |
| server | `server.py` | HTTP routes `/health` `/login` `/api/*` `/mcp` | python unittest + curl smoke in CI |
| insurance | `upstream-carbon/**`, `vendor/**`, `site/public/branding/**` | tracked upstream snapshot, tarballs, brand assets | offline-build check (G6) |

Modules talk through their public interfaces only. Shared hotspots are changed by one ticket at a time: `deps` (`site/package.json`, `site/package-lock.json`), `registry:routes` (`site/src/routes.*`), `styles` (`site/src/index.scss`), `config` (`Containerfile`, `.github/workflows/**`, server env handling). Generated files in `data/` are regenerated by script and never hand-edited.

## Conventions

- Carbon components for all UI; data-driven pages from `data/*.json`; plain JS in `site/` (no TypeScript); Python standard library only in `server.py`.
- Configuration by environment variable (names only: `BONGDESIGN_USER`, `BONGDESIGN_PASS`, `BONGDESIGN_TOKEN`, `BONGDESIGN_OPEN`, `PORT`); secrets never in the repository.
- Branding: Bongbetic red `#e11d2a` is accent only (never fills a control); Carbon blue stays the interactive colour; brand assets are vendored locally, never hotlinked.
- Carbon is Apache-2.0 (IBM attribution in `LICENSE`); no IBM trademarks in branding positions.
- Containers: the existing `Containerfile` only; podman, never Docker.

## How to work here

- **Test-first at the seams.** Every behavior change starts with a failing test at a public interface listed above: one behavior per test, through the public API, doubles only at system boundaries. Commit the failing test (`test(T<nn>): …`) before the code that makes it pass (`feat(T<nn>): …`).
- **One ticket, one branch, one worktree.** Branches are `heimdall/t<nn>-<slug>`; change only the ticket's touch set; stop and report when you need more. Only the ticket holding the `deps` hotspot changes a lockfile.
- **Decisions are recorded, not re-litigated:** `docs/adr/` holds the architecture decisions; a change is a new ADR that supersedes the old one.
- **Never** push to `heimdall/bongdesign` directly, force-push, delete branches, run destructive commands, deploy, or spend money. The orchestrator merges.

## Where things are

- Architecture decisions: `docs/adr/`
- Build state (local, not committed): `.heimdall/` — STATE.md, HANDOFF.md, tickets, packets, reports, progress report
